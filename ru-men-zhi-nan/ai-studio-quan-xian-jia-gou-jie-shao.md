# AI Studio 権限アーキテクチャの紹介

## 権限アーキテクチャ

<figure><img src="../.gitbook/assets/image (397).png" alt=""><figcaption></figcaption></figure>

### 機能レベル（Root）&#x20;

「ある種類の機能」の利用・管理権限を管理するためのもので、例として Agent リスト、ナレッジベースリスト、テンプレートリストなどがあります。この階層は、当該機能に入れるか、新しい項目を作成できるか、その機能のメンバー名簿を管理できるかなどを決定します。

Root の閲覧権限は AI Studio のロール権限設定によって決まります。AI Studio のロール権限については [AI Studio ロール権限の紹介](ai-studio-jue-se-yu-quan-xian-shuo-ming.md) を参照してください。

### 項目レベル（Object）&#x20;

機能内の「個々の項目」の権限を管理するためのもので、例として特定の Agent、特定のナレッジベース、特定のテンプレートがあります。この階層では、単一の項目ごとにメンバーのロールを設定し、誰が編集できるか、誰が利用のみ可能か、誰がメンバーを管理できるかなどを決定できます。

Object の閲覧権限は Root のロール権限設定によって決まります。Root のロール権限については [モジュール権限ロールの紹介](quan-xian-gong-neng-jie-shao.md) の各**リストロール権限**を参照してください。

> 注意：既定では、管理権限を持つロールのみが対応する機能に入り、管理操作を行うことができます。一部の機能が表示されない、または操作を実行できない場合は、「機能レベル」と「項目レベル」の権限が付与されているか管理者に確認してください。

## 権限の判定方法

<figure><img src="../.gitbook/assets/image (398).png" alt=""><figcaption></figcaption></figure>

システムはまずユーザーがその機能で持つ Root 権限を判定し、次にユーザーの Root ロールに応じて、さらに Object 権限を判定する必要があるかどうかを決定します。

* ユーザーがその機能の**リスト管理者**である場合、個別オブジェクトの Object 権限を持っていなくても、その機能内のオブジェクトを管理でき、追加・編集・削除などの操作を実行できます。
* ユーザーがその機能の**リストコラボレーター**または**リストユーザー**である場合は、引き続き Object 権限に従ってアクセス・操作可能なオブジェクトの範囲が判定されます。
* ユーザーがその機能の Root 権限を持たない場合は、その機能ページに入ることも、その機能内のオブジェクトを操作することもできません。

### 注意事項

ユーザーが実際に閲覧・操作できる内容は、Root 権限と Object 権限の設定によって異なります。ユーザーが特定の機能やオブジェクトを閲覧できない場合は、そのユーザーが対応する機能の Root 権限を持っているか、また当該オブジェクトに対応する Object 権限が付与されているかを確認してください。

ユーザーに機能内のすべてのオブジェクトを管理させる必要がある場合は、そのユーザーをその機能の Root Admin に設定できます。特定のオブジェクトのみ操作を許可したい場合は、Object 権限で設定できます。

権限を変更した後、一部のページは再読み込みするか、機能ページに入り直さないと最新の権限結果が表示されないことがあります。



## Root 権限

<figure><img src="../.gitbook/assets/image (347).png" alt=""><figcaption></figcaption></figure>

Root 権限はモジュール全体の最も外側の制御権限であり、ある機能におけるユーザーの全体的な操作範囲を制御するために使用します。Root 権限は通常、以下のロールに分かれます：

* **リスト管理者**
* **リストコラボレーター**
* **リストユーザー**

各 Root ロールが実行できる操作範囲は、機能の設計によって異なります。

ユーザーがある機能の Root 権限を持っている場合にのみ、その機能ページに入ったり、その機能が提供する主要な操作を使用したりできます。例えば Agent、ナレッジベース、テンプレートやその他の機能モジュールに入る場合です。

このうち、**リスト管理者**はその機能における最高の管理権限を持ちます。ユーザーがある機能のリスト管理者である場合、特定の Object 権限を付与されていなくても、その機能内のオブジェクトに対して追加・編集・削除などの管理操作を行うことができます。

## **Object 権限**

<figure><img src="../.gitbook/assets/image (348).png" alt=""><figcaption></figcaption></figure>

Object 権限は、ユーザーが機能内でアクセス・操作できる個別オブジェクトを制御するために使用します。

同一の機能には、異なる Agent、ナレッジベース、テンプレートやその他の項目など、複数のオブジェクトが含まれることがあります。ユーザーがその機能のリスト管理者でない場合、システムは各オブジェクトの Object 権限に従って、ユーザーがそのオブジェクトを閲覧・利用・編集・管理できるかどうかを判定します。

## AI Studio と Root 権限の同期

ログイン後、システムは AI Studio アカウントのその時点の権限をリスト権限に自動的に補完します。

例：アカウントが **AI Studio コラボレーター**の場合、ログイン後に Agent、ナレッジベース、能力（スキル、MCP）、テンプレート（ワークフロー、プロンプト）、分析（レポート）の**リストコラボレーター**権限が自動的に補完されます。

この機能は**ログイン時に、現在権限を持っていない部分のみ同期をトリガーし**、**既存のリスト権限には影響しません**。当該アカウントの AI Studio における権限に変更があっても、権限の自動同期機能はトリガーされません。
