## **ワークフローの作成／編集**

> 注意：編集後に直接「テストプレビュー」でテストできるよう、アシスタント設定からワークフローエディターを開くことをお勧めします。

<figure><img src="../.gitbook/assets/image (220).png" alt=""><figcaption></figcaption></figure>

空白のワークフローを例にすると、画面には既定で1つの **"Start"** ノードが含まれます。このノードをクリックすると、複数の基本変数が表示されます：

| 変数名                       | 説明               | 表示情報                                          |
| -------------------------- | ---------------- | --------------------------------------------- |
| `(x)${{start}.{query}}`    | ユーザーの入力プロンプト         | _ユーザー入力、例：_ `summarize the attached document` |
| `(x)${{start}.{files}}`    | ユーザーがチャット入力エリアに添付したファイルのリスト | `metadata of the files in a JSON array`       |
| `(x)${{start}.{time}}`     | 現在のシステム時刻           | `17:19:13`                                    |
| `(x)${{start}.{date}}`     | 現在のシステム日付           | `2025-06-06 Friday`                           |
| `(x)${{start}.{dateTime}}` | 現在のシステム日付と時刻        | `2025-06-06 Friday 17:19:13`                  |

以下は、基本的なワークフロー操作を示す簡単な例です：

<figure><img src="../.gitbook/assets/image (221).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (222).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (223).png" alt=""><figcaption></figcaption></figure>

1. 新しいワークフローで、「Start」ノードをクリックして基本変数を確認します
2. ノードリストから「Reply」ノードを編集エリアにドラッグ＆ドロップします
3. 「Start」ノードの出力端を「Reply」ノードの入力端に接続します
4. この例では基本変数の内容が表示されます。「Reply」ノードをクリックして編集ウィンドウを開き、入力エリアでアシスタントの返信内容を編集します
5. 「/」を入力すると利用可能なワークフロー変数のリストが表示されます。上記の表を参考に、返信に表示する変数を選択してください
6. 編集が完了したら、機能メニューの「Save」ボタンをクリックし、続いて「Test Preview」をクリックしてワークフローをテストします
7. 「Test Preview」のチャットエリアでファイルを添付しプロンプトを入力して送信すると、アシスタントの処理ステップをリアルタイムで確認できます
8. アシスタントの処理が完了したら、ユーザーはチャットエリアの「Reply」項目を展開してワークフローの結果を確認できます

この手順に沿って、さまざまなノードを試し、自分の利用ニーズに合ったワークフローを構築してみてください！

## ノードのコピー＆ペースト（Clipboard Copy / Paste）

ワークフローはノード設定の素早いコピー＆ペーストをサポートしており、複数の類似ノードを作成したり、既存のロジックをフロー間で移動したりするのに適しています。

<figure><img src="../.gitbook/assets/image (224).png" alt=""><figcaption></figcaption></figure>

使用方法：

* キャンバス上で1つまたは複数のノードを選択します
* コピー／ペースト操作を使用します
* ペースト後、ノードは同じ設定でキャンバスに表示され、差分内容をさらに微調整できます

補足の動作説明：

* ワークフロー間のコピー＆ペースト：ノードをフロー A からコピーしてフロー B に貼り付けでき、フローの組み立てを高速化します。
* 一括操作：複数のノードを一度に選択してコピー＆ペーストでき、ノードの設定内容を保持します。
* 名前衝突の処理：ペースト後にノード名や変数名の重複が生じた場合、システムは保存のために名前の調整を求めることがあります（表示に従って修正してください）。

> 注意：ノード設定で「他のノードの出力変数」を参照している場合、新しいフローに貼り付けた後、上流ノードの接続が不足しているため解析できないことがあります。ペースト後にまず接続と変数参照が完全かどうか確認することをお勧めします。

## 履歴（History）

履歴は、ユーザーがクリックして保存した各内容を保存でき、ユーザーは過去の編集履歴を確認したり、復元によって古いバージョンに戻したりできます。

> 注意：右上の保存ボタンをクリックしないと、内容は履歴に記録されません。

<figure><img src="../.gitbook/assets/image (226).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (227).png" alt=""><figcaption></figcaption></figure>

![](<../.gitbook/assets/image (228).png>)

1. ワークフロー機能メニューで「履歴」をクリックします
2. ポップアップウィンドウの左側はリアルタイムプレビューです
3. 右側はバージョン履歴で、カードをクリックして異なるバージョンに切り替えられます。
   1. 保存される履歴は最大21件で、22件目を保存する際に最も古い記録が削除されます
   2. 特定の履歴を保存したい場合は、ピンアイコンをクリックして固定バージョンとして保存してください。ピン留めできるのは最大20件です
4. 切り替えたいバージョンをクリックします
5. 「復元」をクリックしてワークフローに適用します

## グローバル変数の編集（Global Variables）

グローバル変数は「このワークフローで共有する定数／設定」と考えられ、複数のノードで繰り返し使用される内容、例えば会社のポリシー、口調の規範、固定形式、返信テンプレートの断片、API パラメータの既定値などを置くのに適しています。一元管理することで、複数のノード内で繰り返し修正することを避けられます。

<figure><img src="../.gitbook/assets/image (229).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (230).png" alt=""><figcaption></figcaption></figure>

1. ワークフロー機能メニューで「グローバル変数の編集」をクリックします
2. ポップアップウィンドウで変数内容を新規追加または編集します
3. 完了したら「保存」をクリックしてワークフローに適用します

### 変数の新規追加 / 編集

* 名前：参照用の識別名で、数字と英字のみ使用できます。
* 内容：変数値の本体で、複数行のテキスト（規範、テンプレート、段落など）にできます。

> 注意：変数名を変更した場合、システムはワークフロー内の参照を同期して更新します（実際の画面の表示を基準とすることをお勧めします）。変数を「プレーンテキスト」として手動でノード内容にコピー＆ペーストしたことがある場合、そのテキストは変数参照の範囲には属さないため、自分で更新する必要があります。

### ノードでのグローバル変数の参照

ノード設定（例：LLM ノードの「コンテキスト / Context」やその他の入力欄）で / を入力すると、変数リストから利用可能なグローバル変数を挿入できます。挿入後、システムは変数式の形で表示し、以降は最新の内容が自動的に取り込まれます。

<figure><img src="../.gitbook/assets/image (231).png" alt=""><figcaption></figcaption></figure>

### System Prompt でのグローバル変数の参照

複数の LLM ノードで一貫したロール、口調、出力規範を共有したい場合は、規範をグローバル変数に書き込み、各ノードの System Prompt でその変数を直接参照することをお勧めします。

メリット：規範を更新する際に一度変更するだけで、参照しているすべてのノードに適用できます。

> 注意：保存時に「変数を解析できない / 参照に失敗」などの表示が出た場合は、次の点を確認してください：

1. 変数名に特殊記号や予約語が含まれていない
2. そのノードの欄が変数参照に対応している
3. 変数が正常に保存されている

#### グローバル変数（Global Variables）言語翻訳アシスタント

グローバル変数を一度設定するだけで、ワークフロー全体のすべての AI ノードの出力動作（例：出力言語）を同時に制御できるシーンを示します。ユーザーは各ノードを一つずつ修正しなくても、中国語・英語やその他の言語を素早く切り替えられ、全体の出力の一貫性を確保できます。多言語や多国籍の利用シーンに特に適しています。
