## **Context と System Prompt の使い方**

LLM ノードを設定する際、**コンテキスト（Context）** と **システムプロンプト（System Prompt）** はどちらも指示を含めることができますが、用途が異なり、明確な優先順位があります：

### **コンテキスト（Context）**

> 用途： 動的な入力変数を設定します。モデルの「作業エリア」、つまりモデルが現在参照している内容と考えられます。

**注意事項：**

* **コンテキスト** 欄を使って **クエリテキスト**、**ユーザー入力**、**前のノードのデータ** を渡します。
* `${start.query}` や `${llm-nodeA.result}` などの変数を使用でき、応答をよりパーソナライズまたは文脈化できます。
* ここに短い指示を入れることもできますが、コンテキスト欄は行動規範ではなく **内容** を中心にすべきです。

### **システムプロンプト（System Prompt）**

> 用途： モデルの動作とロールを定義します。このノードの「恒久的な職務記述書」と考えられます。

**注意事項：**

* モデルが **誰であるか**、**どう行動すべきか**、**何を達成すべきか** を定義するために使います。
* システムプロンプト内の指示は、コンテキスト内の指示より **優先されます**。
* 常に次の項目を明確に定義することをお勧めします：
  * **ロール**（例：プロダクトマネージャー、アナリスト、メンター）
  * **タスク目標**（例：レポートを書く、コードを説明する）
  * **口調**（例：フォーマル、フレンドリー）
  * **ツール使用ルール**（ツールを追加している場合）

### **ファイル処理（File Handling）**

**ファイル処理** 設定では、アシスタントが作業エリアでアップロードファイルをどう処理するかをユーザーが定義できます。アシスタントが会話の中でファイル内容（PDF、DOCX、画像など）を読み取り、変換、抽出する必要がある場合に特に便利です。
