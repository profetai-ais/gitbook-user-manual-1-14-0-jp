## **基本設定**

ユーザーは基本設定でナレッジの名前と説明を変更できます。

手順：

1. 「ナレッジ設定メニュー」の _基本設定_ 項目をクリックします
2. 「名前」または「説明」欄のテキストを編集します
3. 「保存」をクリックして設定を完了します

> 注意： インデックスモデルはナレッジ作成時に選択した後、変更できません。

## **データセット**

データセット設定ページでは、ユーザーがファイルをアップロード・管理できます。AI Studio がサポートするファイル形式は次のとおりです：

* 長文のテキスト内容（TXT、Markdown、DOCX、HTML、JSONL、画像のみではない PDF など）
* 構造化データ（CSV、Excel など）

1. 「ナレッジ設定メニュー」の _データセット_ 項目をクリックします
2. 「新規追加/インポート」ボタンをクリックした後、_ファイルインポート_ を選択します
3. 「アップロードエリア」をクリックしてシステムウィンドウを開き、アップロードするファイルを選択し、完了したら _次のページ_ を押します
4. データ処理の部分では、左側の「ファイル処理」オプションでファイル内容を分割する戦略を選択でき、_分割結果を生成_ をクリックすると右側に分割後のデータプレビューが表示されます。処理方法を確認したら _次のページ_ を押します
5. 内容を再度確認したら「アップロード」ボタンをクリックしてファイルをアップロードします
6. ページがデータセット一覧に戻ります。ファイルの状態欄が「完了」と表示されたら、データを使用できます

### ファイルアップロードの制限

データ処理の性能とインデックス品質を確保するため、データセットへのファイルインポート時には以下の制限があります：

| 項目         | 制限             |
| ---------- | -------------- |
| 1回のインポートファイル数の上限 | 最大 **100** 個のファイル |
| 1ファイルのサイズ上限   | 300MB          |

補足説明：

* 上記いずれかの制限を超えると、システムは通知メッセージを表示してアップロードをブロックします。ファイル数を調整するか、ファイルを分割してから再度インポートしてください。
* 大型ファイル（長文の PDF / DOCX など）の場合は、処理時間が長くなりすぎないよう、不要な画像や付録の内容を先に削除することをお勧めします。

#### ダウンロードアクセス制御（Download access control）

データセットの元ファイルのダウンロード動作は「データセットアクセス権限」の影響を受けます：

* 権限を付与されたユーザー：データセット一覧やデータブロック表示で元ファイルをダウンロード／アクセスできます（画面に表示される操作ボタンに従ってください）。
* 権限を付与されていないユーザー：元ファイルをダウンロードまたはアクセスしようとすると、システムがブロックして権限不足を通知します。一部の画面ではダウンロード入口が表示されない、または操作不可になることがあります。

他者にデータセットファイルのダウンロード／アクセスを許可する必要がある場合は、管理者が本ページ下部の「# データセットアクセス権限」ブロックで、指定のデータセットにアクセス可能な組織やユーザーを追加し、設定を保存してください。

#### トラブルシューティング：権限設定の表示が異常

「データセットアクセス権限」ページで権限の詳細が表示されない、ブロックが空白、展開しても内容がない場合は、順に試してください：

1. 「更新」をクリックして一覧を再読み込みするか、他のメニューに切り替えてから戻します。
2. 左側の「データセット」エリアで対象のファイル／データセットが選択されているか確認します。
3. 現在のアカウントが「AI Studio 管理者／ナレッジベース管理者／分野の専門家／コラボレーター」など、ナレッジベースを管理できる権限を備えているか確認します。なければ、管理者に協力を依頼してください。

## **データセット追加時のデータ処理**

ファイルアップロード後のデータ処理は、以下の2つの形式をサポートします：

* **直接分割**：ユーザーのオプションを適用して分割します
* **QA 分割**：Q&A 内容のファイルに対して、質問を基準に分割します

#### **直接分割**

元の内容に明確な質問応答構造がない場合や、ユーザーがデータ分割を素早く作成したい場合は、「直接分割」モードを有効にできます。システムは設定に従って自動的に段落を分割します。

<table><thead><tr><th width="180">処理方法</th><th>説明</th></tr></thead><tbody><tr><td>自動</td><td>システムは既定で、入力内容の長さと言語構造に基づいて自動的に分割します。素早く使い始めたい、独自のルールが不要な場面に適しています。分割方法を指定しない場合、システムは改行や句点などの一般的な記号で初期分割を行います。</td></tr><tr><td>Token 分割</td><td>設定した分割 token 長に基づいてテキストを分割します。意味の断片化や文脈の切断を避けるため、1段落の長さは 100～1000 tokens の範囲に収めることをお勧めします。</td></tr><tr><td>カスタムルール</td><td>より細かい制御を提供します。段落の長さ（推奨 100～1000）と重複範囲（100 tokens など）の設定に加え、分割を制御する区切り文字オプションが追加されています。</td></tr><tr><td>Regex 分割</td><td>特定の文字（<code>\\n</code>、<code>。</code>、<code>,</code>、<code>;</code> など）でテキストを分割します。複数の記号を組み合わせて使え、一般的な自然言語処理の場面に適しています。</td></tr></tbody></table>

<table><thead><tr><th width="180">処理方法のオプション</th><th width="200">適用される分割処理方法</th><th>説明</th></tr></thead><tbody><tr><td>理想的な長さでの分割</td><td>Token 分割、カスタムルール</td><td>各段落の目標の長さ（token 単位）を設定できます。数値が小さいほど分割は細かくなりますが、文脈のつながりが弱まることがあります。数値が大きい場合は、文脈の一貫性を保つため重複範囲を併用する必要があります。</td></tr><tr><td>重複範囲</td><td>Token 分割、カスタムルール</td><td>各段落が前の段落と重複する token 数（100 など）を定義し、文脈の継続性を高めます。推奨値は 1 から理想的な長さ - 1 の間です。マルチターン会話や技術文書など、高い文脈性が必要な内容の処理に適しています。</td></tr><tr><td>カスタム区切り文字</td><td>カスタムルール</td><td>分割点を識別する記号をセミコロンで区切って設定します。例：<code>;; ;'';</code> を設定すると、文中に <code>;</code>、<code>(スペース)</code>、<code>''</code> が出現したときに分割します。</td></tr><tr><td>ルール</td><td>Regex 分割</td><td>ユーザーが分割の Regex 構文をカスタマイズします。下部のプリセット分割例をクリックして編集できます：<code>.+\\n?</code>（改行で分割）、<code>[^。]+。?</code>（中国語の句点で分割）。</td></tr><tr><td>最後の改行文字を削除</td><td>Regex 分割</td><td>段落末尾の空行 <code>\\n$</code> 記号を自動的に削除するかどうか。</td></tr></tbody></table>

> 推奨： Token 分割 + 重複範囲 を使うと、意味と文脈の完全性を効果的に保ち、文が途中で切断されて情報が断片化・欠落するのを避けられます

#### **QA 分割**

質問応答型のファイル内容（FAQ、カスタマーサポート記録、インタビュー原稿など）を処理する際は、QA 分割設定を通じて構造の識別度と意味の明確さを高められます。システムは質問と回答のブロックを識別・分割するのを助ける以下のパラメータを提供します。

<table><thead><tr><th width="200">オプション</th><th>説明</th></tr></thead><tbody><tr><td>質問プレフィックス</td><td>質問の冒頭を識別する文字列（<code>Q:</code>、<code>質問：</code> など）を指定します。システムはこれを新しい質問段落の起点として識別します。</td></tr><tr><td>回答プレフィックス</td><td>回答の冒頭を識別する文字列（<code>A:</code>、<code>回答：</code> など）を指定し、質問に対応する解答内容を識別します。</td></tr><tr><td>プレフィックスを削除</td><td>有効にすると、質問と回答の段落冒頭のマーク文字列（<code>Q:</code>、<code>A:</code> など）を自動的に削除します。</td></tr><tr><td>プレフィックス表現</td><td>質問と回答のプレフィックスの識別に正規表現（Regex）の使用をサポートし、形式が一定でない場合や大量のデータ変換の場面に適しています。例：<code>^Q[0-9]*:</code> は複数の質問番号に一致できます。</td></tr><tr><td>最後の改行文字を削除</td><td>有効にすると、各 QA ブロック末尾の余分な改行文字を自動的に除去します。</td></tr></tbody></table>

## **データブロック内容の編集**

ユーザーはデータブロックの内容を最適化し、LLM が回答を生成する際に引用するデータの正確性を高められます。例えば、Q&A タイプのデータブロックに、考えられる質問の表現方法を追加します。

<figure><img src="../.gitbook/assets/image (60).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (61).png" alt=""><figcaption></figcaption></figure>

1. データブロックの「編集」ボタンをクリックした後、_編集_ を選択します
2. ポップアップウィンドウ右上の「編集」ボタンをクリックして編集インターフェースの欄を開きます
3. _質問_ 見出しの右側の「+」ボタンをクリックして質問を追加します
4. 質問内容を入力した後、インターフェース右上の「✔️」ボタンをクリックして変更を保存します

## **参照ファイルの作成**

AI Studio はデータセットの内容を引用して回答を生成する際に、関連ファイルを参照ソースとして追加できます。例えば PDF や PPT の特定ページや画像などを提供します。

<figure><img src="../.gitbook/assets/image (63).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (64).png" alt=""><figcaption></figcaption></figure>

1. 「参照ファイル」タブをクリックします
2. 「+作成」ボタンをクリックしてシステムウィンドウを開き、アップロードするファイルを選択し、完了したら _確認_ を押します
3. _参照ファイル一覧_ でファイルが正しくアップロードされたことを確認したら、「データブロック」タブをクリックします
4. データブロックの「編集」ボタンをクリックした後、_編集_ を選択します
5. 左側の「ファイルをリンク」をクリックします
6. 「+作成」ボタンをクリックしてファイル追加ウィンドウを開きます
7. 「ファイルメニュー」をクリックして参照ファイルを選択した後、_確認_ を押して参照ファイルの添付作成を完了します

## **テスト**

データセットを作成した後、ユーザーは「テスト」機能を使って質問でき、回答を生成する際にどのデータブロックの内容が引用されたかを確認できます。また、検索パラメータを調整して検索結果を採点し、データ内容を最適化して引用データの正確性を高められます。

1. 「ナレッジ設定メニュー」の _テスト_ 項目をクリックします
2. 「検索テキスト」見出しの右側の _歯車ボタン_ をクリックして検索パラメータ設定を開きます
3. 一般的には下部の「採点を有効化」をチェックすることをお勧めします
4. 「LLM 採点モデル」メニューをクリックして使用するモデルを選択します
5. 「スコア閾値」設定を調整して検索結果のスコア要件を絞り込みます。結果がスコア要件に達した場合のみ _採点結果_ に関連情報として表示されます
6. 「確認」ボタンをクリックしてパラメータ設定を保存します
7. 「検索テキスト」に照会したい内容／質問を入力した後、_照会_ ボタンを押して送信します
8. 検索結果は「リコール結果」に一覧表示され、リコールスコアの高低に従って並べ替えられます
9. いずれかの _リコール結果_ をクリックすると完全な情報内容を確認でき、「インデックス」タブをクリックすると、システムがそのデータブロックの検索に使用したインデックスを確認できます
