# スケジュール

## はじめに

<figure><img src="../.gitbook/assets/image (385).png" alt=""><figcaption></figcaption></figure>

Schedule を使うと、ユーザーはスケジュールタスクを作成し、指定した Agent が設定した時刻や周期に従って自動的に指示を実行できます。ユーザーは Schedule を通じて、毎日の要約、定時通知、データ照会、レポート生成、自動化フローなどの定型タスクを定期的に実行できます。

スケジュール設定を使えば、ユーザーは手動で Agent の会話を開かなくても、Agent に指定した時刻にタスクを自動実行させ、毎回の実行結果と記録を保持できます。

## スケジュールの作成

### スケジュール管理ページから作成する

<figure><img src="../.gitbook/assets/image (381).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (382).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (384).png" alt=""><figcaption></figcaption></figure>

1. スケジュールタブに切り替えます
2. 右上の「新規追加」をクリックすると「スケジュールの新規追加」ウィンドウが開き、新しいスケジュールタスクを作成できます
3. スケジュール名を入力します
4. スケジュールをトリガーする Agent を選択します。一度選択すると変更できません
5. スケジュールの実行モードを選択します
   * 独立モード： 各スケジュール実行を独立したタスクとして扱います。コンテキストを蓄積する必要のない単発実行のシーンに適しています
   * コンテキストモード： スケジュールが実行の文脈を継承・蓄積します。継続的な追跡、情報の蓄積、タスク状態の継続が必要なシーンに適しています
6. Agent が毎回の実行で完了すべきタスク内容を入力します。指示はタスクの目標、出力形式、注意すべき条件をできるだけ明確に記述し、スケジュール実行結果の安定性を高めるべきです
7. 時間範囲を入力します。システムは選択したタイムゾーンに従ってスケジュール実行時刻を計算します
8. スケジュールの時間周期を選択します。スケジュールは以下の3種類の周期モードをサポートします：
   * 周期実行： 固定間隔で繰り返し実行するスケジュールの設定に使います。例えば**30分ごと**に設定すると、スケジュールは**開始時刻**から30分ごとに自動実行されます
   * 指定時刻： スケジュールが指定の日時に実行するよう設定するために使います。ユーザーは実行する日時を選択する必要があります。このモードは、特定の時刻に一度だけ実行する、またはシステム設定に従って指定時刻にトリガーするタスクに適しています
   * カスタム： より複雑なスケジュールルールの設定に使います。ユーザーは自然言語の記述を入力してシステムに Cron を生成させることも、Cron 式を直接入力することもできます
9. 実行上限を選択します。少なくとも1つの使用制限を有効にする必要があります。有効にした使用制限のいずれかが設定した閾値に達すると、スケジュールは自動的に無効化されます。スケジュールは以下の停止条件をサポートします：
   * Date： 終了日を設定します。指定日に達すると、スケジュールは実行を停止します
   * Count： 最大実行回数を設定します。指定回数に達すると、スケジュールは実行を停止します
   * Token： 最大 Token 使用量を設定します。指定 Token 数に達すると、スケジュールは実行を停止します
10. 通知対象を設定します。ユーザーはスケジュール完了後に指定ユーザーへ通知するかどうかを設定でき、現在スケジュールはメール通知と webhook モードをサポートします：
    * Email 通知： システムが電子メールで指定の受信者に通知します
    * Webhook： ユーザーは外部 URL を設定できます。スケジュール実行が完了すると、システムは結果を POST 方式で指定の外部サービスに送信できます
11. 設定が完了したら「新規追加」をクリックして設定を完了します

### Agent 設定ページから作成する

<figure><img src="../.gitbook/assets/image (386).png" alt=""><figcaption></figcaption></figure>

入口は Agent 設定ページのスケジュール管理にあります。追加の流れは [スケジュール管理ページから作成する](pai-cheng.md#cong-pai-cheng-guan-li-ye-mian-jian-li) を参照してください。唯一異なる点は、Agent 設定ページでは他の Agent を別途設定できないことです。



## ログの確認

スケジュール詳細ページで**ログ**をクリックすると、そのスケジュールの実行記録を確認できます。

<figure><img src="../.gitbook/assets/image (380).png" alt=""><figcaption></figcaption></figure>

ログ一覧には、各実行のタイトルと状態が表示されます。ユーザーは記録をクリックして、その実行の詳細内容を確認できます。

実行結果は会話形式で表示され、Agent の返信内容、実行コスト、関連操作を含みます。ユーザーは実行結果をコピーしたり、ログ一覧に戻って他の記録を確認したりできます。

ログは、スケジュールが正常に実行されたか、Agent の返信内容が期待どおりか、各実行の結果に後続処理が必要かをユーザーが確認するのに役立ちます。



## 注意事項

スケジュールは設定したタイムゾーンと周期に従って自動実行されます。作成前に、時間範囲、開始時刻、周期、実行上限の条件が正しいか確認してください。

スケジュールの実行に失敗した場合は、ログでエラー記録と実行結果を確認できます。スケジュールが期待どおりに実行されない場合は、スケジュールが有効か、停止条件が閾値に達していないか、Agent が引き続き正常に使用できるかを確認してください。

スケジュールタスクが外部サービスを呼び出したり通知を送信したりする場合は、Webhook URL、通知方法、受信者の設定が正しいか確認してください。
